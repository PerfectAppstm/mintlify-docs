---
title: "Database Credential Types in 2AM Database++ Projects"
sidebarTitle: "Credentials"
description: "Configure database credentials using direct values, dotenv files, or AWS Secrets Manager — each method suited to different environments."
---

Keeping database credentials out of your source code is one of the most important security practices you can adopt. 2AM Database++ supports three credential types — **Direct**, **Dotenv**, and **AWS Secrets Manager** — so you can choose the approach that fits each environment's security requirements. You define the credential type inside each environment block in `configuration.yml`, and the tool resolves the actual values at runtime.

<Tabs>
  <Tab title="Direct">
    With the **Direct** credential type you supply your database connection details as plain values directly inside `configuration.yml`.

    <Warning>
      Direct credentials are committed to `configuration.yml` and therefore to your version control history. Use this type only for local development or throwaway environments, never for production or any environment that contains sensitive data.
    </Warning>

    <ParamField body="username" type="string" required>
      The username used to authenticate with the database server.
    </ParamField>

    <ParamField body="password" type="string" required>
      The password for the database user.
    </ParamField>

    <ParamField body="host" type="string" required>
      The hostname or IP address of the database server (e.g. `localhost` or `db.example.com`).
    </ParamField>

    <ParamField body="database" type="string" required>
      The name of the target database on the server.
    </ParamField>

    <ParamField body="port" type="number" required>
      The TCP port the database server listens on (e.g. `3306` for MySQL, `5432` for PostgreSQL, `1433` for MSSQL).
    </ParamField>

    <ParamField body="ssl.enabled" type="boolean">
      Set to `true` to require an SSL/TLS connection to the database server.
    </ParamField>

    <ParamField body="ssl.caFilePath" type="string">
      Path to the PEM-encoded Certificate Authority (CA) file used to verify the server certificate.
    </ParamField>

    <ParamField body="ssl.certFilePath" type="string">
      Path to the PEM-encoded client certificate file for mutual TLS authentication.
    </ParamField>

    <ParamField body="ssl.keyFilePath" type="string">
      Path to the PEM-encoded private key file that corresponds to `ssl.certFilePath`.
    </ParamField>

    <ParamField body="ssl.verifyPeer" type="boolean">
      When `true`, the tool verifies that the server certificate is signed by a trusted CA. Disable only in controlled development environments.
    </ParamField>

    **Example `configuration.yml` — Direct credentials**

    ```yaml
    name: My Project
    identifier: my-project
    trackingTable: _migrations
    databaseType: mysql

    environments:
      - name: local
        credentialType: direct
        username: root
        password: secret
        host: localhost
        database: my_app
        port: 3306
        ssl:
          enabled: false
    ```
  </Tab>

  <Tab title="Dotenv">
    With the **Dotenv** credential type, 2AM Database++ reads your connection details from a `.env` file at runtime. Your `configuration.yml` stores only the variable *names*, not the values themselves, so you can safely commit the configuration file while keeping the actual secrets in a `.env` file that is excluded from version control.

    <ParamField body="dotenvFileName" type="string" required>
      The filename of the dotenv file to read, relative to your project root (e.g. `.env`, `.env.local`, `.env.staging`).
    </ParamField>

    <ParamField body="usernameKey" type="string" required>
      The variable name in the `.env` file whose value is the database username.
    </ParamField>

    <ParamField body="passwordKey" type="string" required>
      The variable name in the `.env` file whose value is the database password.
    </ParamField>

    <ParamField body="hostKey" type="string" required>
      The variable name in the `.env` file whose value is the database host address.
    </ParamField>

    <ParamField body="databaseKey" type="string" required>
      The variable name in the `.env` file whose value is the database name.
    </ParamField>

    <ParamField body="portKey" type="string">
      The variable name in the `.env` file whose value is the database port. If omitted, the default port for the configured `databaseType` is used.
    </ParamField>

    <ParamField body="sslKey" type="string">
      The variable name whose value enables SSL. Accepted truthy values are `true`, `yes`, `on`, and `1`.
    </ParamField>

    <ParamField body="sslCaFilePathKey" type="string">
      The variable name whose value is the path to the SSL CA file.
    </ParamField>

    <ParamField body="sslCertFilePathKey" type="string">
      The variable name whose value is the path to the SSL client certificate file.
    </ParamField>

    <ParamField body="sslKeyFilePathKey" type="string">
      The variable name whose value is the path to the SSL private key file.
    </ParamField>

    <ParamField body="sslVerifyPeerKey" type="string">
      The variable name whose value controls peer certificate verification. Accepted truthy values are `true`, `yes`, `on`, and `1`.
    </ParamField>

    **Example `.env` file**

    ```env
    DB_USER=app_user
    DB_PASSWORD=supersecret
    DB_HOST=db.example.com
    DB_NAME=my_app
    DB_PORT=5432
    DB_SSL=true
    DB_SSL_CA=/etc/ssl/certs/ca.pem
    DB_SSL_CERT=/etc/ssl/certs/client-cert.pem
    DB_SSL_KEY=/etc/ssl/private/client-key.pem
    DB_SSL_VERIFY_PEER=true
    ```

    **Matching `configuration.yml`**

    ```yaml
    name: My Project
    identifier: my-project
    trackingTable: _migrations
    databaseType: postgresql

    environments:
      - name: staging
        credentialType: dotenv
        dotenvFileName: .env
        usernameKey: DB_USER
        passwordKey: DB_PASSWORD
        hostKey: DB_HOST
        databaseKey: DB_NAME
        portKey: DB_PORT
        sslKey: DB_SSL
        sslCaFilePathKey: DB_SSL_CA
        sslCertFilePathKey: DB_SSL_CERT
        sslKeyFilePathKey: DB_SSL_KEY
        sslVerifyPeerKey: DB_SSL_VERIFY_PEER
    ```

    <Tip>
      Add your `.env` files to `.gitignore` so they are never committed to version control. Your `configuration.yml` is safe to commit because it contains only variable names.
    </Tip>
  </Tab>

  <Tab title="AWS Secrets Manager">
    With the **AWS Secrets Manager** credential type, 2AM Database++ retrieves your database credentials from a secret stored in [AWS Secrets Manager](https://aws.amazon.com/secrets-manager/) at runtime. Your `configuration.yml` references the secret path and the key names within that secret — no passwords ever touch the project file.

    <ParamField body="path" type="string" required>
      The full ARN or name path of the secret in AWS Secrets Manager (e.g. `prod/my-app/database`).
    </ParamField>

    <ParamField body="region" type="string" required>
      The AWS region where the secret is stored (e.g. `us-east-1`, `eu-west-2`).
    </ParamField>

    <ParamField body="usernameKey" type="string" required>
      The key inside the secret's JSON value that holds the database username.
    </ParamField>

    <ParamField body="passwordKey" type="string" required>
      The key inside the secret's JSON value that holds the database password.
    </ParamField>

    <ParamField body="hostKey" type="string" required>
      The key inside the secret's JSON value that holds the database host address.
    </ParamField>

    <ParamField body="databaseKey" type="string" required>
      The key inside the secret's JSON value that holds the database name.
    </ParamField>

    <ParamField body="portKey" type="string">
      The key inside the secret's JSON value that holds the database port. If omitted, the default port for the configured `databaseType` is used.
    </ParamField>

    <ParamField body="sslKey" type="string">
      The key inside the secret whose value enables SSL. Accepted truthy values are `true`, `yes`, `on`, and `1`.
    </ParamField>

    <ParamField body="sslCaFilePathKey" type="string">
      The key inside the secret whose value is the path to the SSL CA file.
    </ParamField>

    <ParamField body="sslCertFilePathKey" type="string">
      The key inside the secret whose value is the path to the SSL client certificate file.
    </ParamField>

    <ParamField body="sslKeyFilePathKey" type="string">
      The key inside the secret whose value is the path to the SSL private key file.
    </ParamField>

    <ParamField body="sslVerifyPeerKey" type="string">
      The key inside the secret whose value controls peer certificate verification. Accepted truthy values are `true`, `yes`, `on`, and `1`.
    </ParamField>

    **Example `configuration.yml` — AWS Secrets Manager**

    ```yaml
    name: My Project
    identifier: my-project
    trackingTable: _migrations
    databaseType: mssql

    environments:
      - name: production
        credentialType: awsSecretsManager
        path: prod/my-app/database
        region: us-east-1
        usernameKey: username
        passwordKey: password
        hostKey: host
        databaseKey: dbname
        portKey: port
        sslKey: ssl
        sslCaFilePathKey: sslCaFilePath
        sslCertFilePathKey: sslCertFilePath
        sslKeyFilePathKey: sslKeyFilePath
        sslVerifyPeerKey: sslVerifyPeer
    ```

    <Info>
      Your AWS Access Key ID and Secret Access Key are **not** stored in `configuration.yml`. You enter them once through the 2AM Database++ desktop application or the `2am-smt` CLI connection setup, and they are saved in the tool's own local configuration — separate from your project files.
    </Info>
  </Tab>
</Tabs>
